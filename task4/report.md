## 4.1 从浮点数到低比特

### 理论显存下界

$$
M_{weight}=\frac{P\times b}{8}\ \text{Bytes}
$$

同一组权重从 FP32 换成 FP16/BF16 → 1/2，INT8 → 1/4，INT4 → 1/8。

**但"理论"两个字很重要**：真实系统还要额外保存

- **Scale / Zero-point**（量化元数据，粒度越细开销越大）；
- **KV Cache**（Task 3 的主角，随 batch × 上下文增长）；
- **Activation**（尤其 prefill 阶段的大激活）；
- **临时 Workspace**（GEMM 的中间结果、通信 buffer）。

所以"权重省 4 倍"不等于"显存省 4 倍"，也不等于"延迟变 1/4"（见下文）。

### 量化公式

$$
q=\operatorname{clip}\!\left(\operatorname{round}\!\left(\frac{x}{s}\right)+z,\ q_{min},\ q_{max}\right),
\qquad \hat{x}=s(q-z)
$$

- `s` 是 **Scale**：一个整数刻度代表多少实数；
- `z` 是 **Zero-point**：整数域的零点，用来对齐实数 0；
- **对称量化**令 `z = 0`（适合正负分布大致对称的权重），**非对称量化**允许 `z ≠ 0`，能更充分地利用不对称的取值范围（如 ReLU 之后的激活全为正）。

### PTQ 与 QAT

| | PTQ（Post-Training Quantization） | QAT（Quantization-Aware Training） |
|---|---|---|
| 时机 | 训练**之后**，直接量化已有权重 | 训练**过程中**就插入伪量化节点 |
| 需要什么 | 少量**校准数据**（几百条样本，前向即可） | 完整训练/微调流程 + 数据 + 算力 |
| 精度 | 8 bit 通常几乎无损；4 bit 需要更精细的方法 | 更好，尤其是极低比特 |
| 代价 | 便宜（分钟~小时级） | 昂贵（重训） |
| 本题关注 | **是** | 只是背景（4.4 延伸） |

**为什么 PTQ 不用重训却仍然要看校准数据？** 因为量化不是纯数学操作，它要**观察数据的实际取值范围**才能定出好的 `s`（和 `z`）。这件事有两点很关键：

1. **`s` 依赖数据的动态范围**。`s` 定小了会 clip 掉大值（截断误差），定大了会让普通值挤在很少的整数刻度上（舍入误差）。要选得好，就必须知道激活/权重的真实分布 —— 这只能靠喂几批真实数据前向一遍来观测。
2. **激活是动态的，权重是静态的**。权重在训练后就固定了，可以离线慢慢算；但激活每个 token 都不同，必须用**代表性的校准集**去估计它的典型范围，并据此确定 per-tensor / per-channel 的 scale。

所以 PTQ 的"不重训"是指**不更新参数**，而不是"不看数据"——校准数据的作用是**观测分布、定 scale、评估量化误差**。

### Weight-only 与 W8A8

| 方案 | 权重 | 激活 | 省什么 | 典型场景 |
|---|---|---|---|---|
| **Weight-only**（W4A16 等） | INT4 | FP16 | 权重**存储 + 带宽** | 显存受限、Decode 带宽瓶颈（LLM 推理主流） |
| **W8A8** | INT8 | INT8 | 权重 + 激活的存储/带宽，**还能用整数 Tensor Core 提速** | 需要真正降低计算/提升吞吐的场景 |

关键差别：Weight-only 只解决了"权重读不动"的问题，**计算仍在 FP16 上做**（要先把权重反量化回 FP16），所以对算力没有帮助；W8A8 才能同时吃到"整数 GEMM"的吞吐收益，但激活量化更难（见 Outlier）。

### Per-tensor / Per-channel / Per-group：谁在共享同一组 Scale 和 Zero-point？

| 粒度 | 共享范围 | 需要几组 `s/z` | 精度 | 元数据开销 | Kernel 复杂度 |
|---|---|---|---|---|---|
| **Per-tensor** | 整个张量共用一组 | 1 | 最低（被极值主导） | 可忽略 | 最简单 |
| **Per-channel** | 每个输出通道一组 | `C_out` 组 | 中 | 小 | 中（需按 channel 取 scale） |
| **Per-group**（如 group=128） | 每 G 个元素一组 | `C_out × C_in/G` 组 | 高（能贴合局部动态范围） | 较大 | 较高（Kernel 要按 group 取 scale） |

规律：**粒度越细 → 越能保住精度 → 但元数据更多、Kernel 更复杂**（因为 scale 的加载与计算变得更不规则）。这也是量化工程里的核心权衡：GPTQ/AWQ 主流用 group=128 就是为了在精度和开销之间取平衡。

### Activation Outlier：为什么少数大值会毁掉整张量

LLM 的激活里存在**系统性的离群值**：某些固定的 channel 上会出现比典型值大 20~100 倍的数值（这是 Transformer 架构本身带来的，不是噪声）。

如果按 **per-tensor** 量化激活：

```text
s = max|X| / 127     ← 被那个巨大的 outlier 决定
普通值 x = 典型的 0.1 × outlier
   → q ≈ 127 × 0.1 / 100 = 0.127 → round → 0    ← 大量普通值直接变成 0 或 1
```

也就是：**range 被 outlier 拉开，量化步长 `s` 变大，绝大多数普通值挤在很少的几个整数刻度上，量化信噪比崩溃。** 这是"激活比权重难量化"的根本原因，也是 SmoothQuant 要解决的问题。

### 手算一：同一个向量量化成 INT8 和 INT4

给定 `x = [-1.0, -0.4, 0.2, 0.9]`，约定：`q ∈ [-127,127]` / `q ∈ [-7,7]`，`s = max|x|/q_max`，`z = 0`，Round-to-nearest 后 Clip。

#### (a) 对称 Per-tensor INT8

`s = 1.0 / 127 = 0.0078740157…`

| `x` | `x / s` | `q` | `x̂ = s·q` | 绝对误差 | 相对误差 |
|---|---|---|---|---|---|
| -1.0 | -127.0000 | **-127** | -1.00000000 | 0.00000000 | 0.00% |
| -0.4 | -50.8000 | **-51** | -0.40157480 | 0.00157480 | 0.39% |
| 0.2 | 25.4000 | **25** | 0.19685039 | 0.00314961 | 1.57% |
| 0.9 | 114.3000 | **114** | 0.89763780 | 0.00236220 | 0.26% |

- **Scale**：`s = 1/127 ≈ 0.0078740157`
- **最大绝对误差**：`0.00314961`（出现在 `x = 0.2`）

#### (b) 对称 Per-tensor INT4

`s = 1.0 / 7 = 0.1428571429…`

| `x` | `x / s` | `q` | `x̂ = s·q` | 绝对误差 | 相对误差 |
|---|---|---|---|---|---|
| -1.0 | -7.0000 | **-7** | -1.00000000 | 0.00000000 | 0.00% |
| -0.4 | -2.8000 | **-3** | -0.42857143 | 0.02857143 | 7.14% |
| 0.2 | 1.4000 | **1** | 0.14285714 | 0.05714286 | **28.57%** |
| 0.9 | 6.3000 | **6** | 0.85714286 | 0.04285714 | 4.76% |

- **Scale**：`s = 1/7 ≈ 0.1428571429`
- **最大绝对误差**：`0.05714286`（出现在 `x = 0.2`）

> 上面的数字由 `scripts/quant_check.py` 复算得到，可执行 `python3 task4/scripts/quant_check.py` 核对。

#### 回答：Bit 数减少以后，哪些数最先失去精度？

**是绝对值最小的那些非零元素，而不是最大的。**

理由可以直接从公式看出来：

- 绝对误差的上界是 `s/2`，**所有元素一样**（同一个 tensor 内 `s` 相同）；
- 相对误差 `≈ (s/2) / |x|`，**与 `|x|` 成反比** → 值越小，相对误差越大；
- 而 `|x| = max|x|` 的那个元素恰好映射到 `q_max`，**可以被精确表示**（本例 `-1.0` 误差为 0）。

本例中：

| | INT8 | INT4 | 变化 |
|---|---|---|---|
| `x = 0.2`（最小非零值）的相对误差 | 1.57% | **28.57%** | ×18.2 |
| `x = -1.0`（最大绝对值） | 0% | 0% | 不变 |
| `s` | 0.0079 | 0.1429 | ×18.1 |

`s` 放大约 18 倍（127/7），**相对误差就跟着放大 18 倍**，首当其冲的就是小值。

工程含义（也是为什么量化里在意"细粒度"）：
1. 减小 `s` 是提升精度的唯一杠杆 → 用 **per-channel / per-group** 让小范围内的 `s` 更小；
2. 小值大量丢精度正是 **outlier 拉开 range** 的直接后果，于是有了 SmoothQuant 的"把难度搬给权重"；
3. 对权重量化特别友好的原因也在这里：权重分布相对平滑、没有极端 outlier，per-channel INT4 就能保住精度。

### 模型变小，为什么不一定等比例变快

Weight-only INT4 的权重只有 FP16 的 1/4，但端到端延迟不会变成 1/4，因为实际速度还取决于：

1. **硬件有没有对应的低比特计算单元**：如果 GPU 没有 INT4 的 Tensor Core 路径，Kernel 只能用 INT4 存储、计算时反量化回 FP16 → 省了带宽，但计算路径没变；
2. **Kernel 是否真的走低比特路径**：很多实现只是"量化存储 + 反量化计算"，反量化本身要额外指令、额外寄存器；
3. **是否需要反量化（dequant）**：反量化要读 scale、做乘加、再喂给 FP16 MMA，引入的 non-matmul 开销可能吃掉收益；
4. **当前瓶颈到底在哪**：
   - 如果瓶颈是**权重带宽**（大 batch / Decode 单请求），量化几乎线性提速；
   - 如果瓶颈是 **Activation / KV Cache 带宽**，权重怎么压都没用（Task 3 的结论）；
   - 如果是**通信**（TP/PP 场景），权重压缩只减少传输量，不改通信次数与延迟；
   - 如果是**算力**（prefill 大形状），Weight-only 根本不省算力，只有 W8A8 才有帮助；
5. **小 batch / 小 shape 时被 launch 与调度开销主导**：kernel 再快，固定开销不变。

## 4.2 三种 PTQ 思路

三篇论文都按 `Abstract + Introduction + Method + 主要结果表` 读，重点是抓住方法之间的差别。

### 4.2.1 SmoothQuant：把难量化的部分搬一搬

**Q1：为什么 LLM 的 Activation 往往比 Weight 更难量化？**

- **权重是静态的**：训练完就固定，分布平滑、没有极端 outlier，per-channel INT8 几乎无损；
- **激活是动态的**：每个 token 都不同，而且存在**系统性的 channel-wise outlier**（少数 channel 的幅值大 20~100 倍）；
- 更麻烦的是，**权重好量化 + 激活难量化会让两者无法同时用 INT8**：因为 `Y = XW`，只要有一边 range 被 outlier 拉大，per-tensor 的整型 GEMM 就没法用。

**Q2：SmoothQuant 如何通过数学等价的缩放，把 Activation Outlier 的量化难度迁移到 Weight？**

它引入 per-channel 的缩放因子 `s_j`，做一个**数学上恒等的变换**：

$$
Y = (X\,\mathrm{diag}(s)^{-1})\;(\mathrm{diag}(s)\,W)
$$

- 激活的第 `j` 个输入通道**除以** `s_j` → 幅值被压平（outlier 被缩小，普通值被放大，整条 channel 的动态范围变窄）；
- 权重的第 `j` 个输入通道**乘以** `s_j` → 权重的 range 被相应放大；
- 因为乘的是对角矩阵，**结果完全不变**（等价变换），但"量化难度"被从激活搬到了权重上。

`α` 参数控制迁移强度，典型取 `s_j = max|X_j|^α / max|W_j|^(1-α)`，`α ≈ 0.5`：让激活和权重**同样好量化**，从而两边都能用 per-tensor INT8。

**Q3：为什么它适合 W8A8？Calibration Data 在这里用来观察什么？**

- **适合 W8A8**：它的目标就是让激活也能安全地量化到 INT8，从而**用上整数 Tensor Core 的 W8A8 GEMM**（真正降低计算时间，而不只是省存储）。这是它和 GPTQ/AWQ（weight-only）最大的区别。
- **校准数据用来观察**：per-channel 激活幅值的分布（最大值或高分位数），据此算出 `s_j` 与静态 scale；同时用来评估不同 `α` 下的量化误差，挑出最合适的迁移强度。校准量很小（几百条样本足够），因为只需要"看清 outlier 在哪些 channel、有多大"。

### 4.2.2 GPTQ：量化一个权重时，也看看它对输出有多重要

**Q1：GPTQ 为什么属于 Weight-only PTQ？**

因为它**只量化权重**（典型 3~4 bit），激活保持 FP16 不动。它不改变计算的数值类型，收益来自**权重存储与读带宽的下降**——这正好对应 Decode 阶段的瓶颈。它不做 W8A8 的整数 GEMM，所以不省算力。

**Q2：为什么它不只看单个权重的数值误差，还要近似考虑这一层输出的重构误差？**

因为**权重误差只有在影响输出时才重要**。GPTQ 的目标函数是层输出的重构误差：

$$
\arg\min_{\hat{W}} \|WX - \hat{W}X\|^2
$$

而不是朴素的 `‖W − Ŵ‖²`。差别在于：输入激活 `X` 的协方差（`H = 2XXᵀ`，即 Hessian）决定了"哪些方向重要"——

- 如果某个权重方向对应的输入激活很大，那么该方向上的权重误差会被放大到输出上 → **必须量得更准**；
- 反之，对输出影响很小的权重方向，可以承受更大的误差。

所以 GPTQ 是**按"对输出的敏感度"分配量化误差的**，而不是对所有元素一视同仁。

**Q3：“逐层处理”“二阶信息”和“一次性量化”分别在解决什么问题？**

| 概念 | 解决什么问题 |
|---|---|
| **逐层处理（layer-wise）** | 一次只量化一层，且该层的输入用**已经量化好的前层输出**来计算 → 避免"前层误差累积、后面越错越多"，也让问题从"整个网络"缩小成"一层的最小二乘" |
| **二阶信息（Hessian ≈ 2XXᵀ）** | 提供"哪个权重方向重要"的度量，让误差往不重要的权重上放（精度显著好于只用一阶/均匀误差） |
| **一次性量化（one-shot / lazy batch update）** | OBQ 类方法逐权重做最优选择在 7B/70B 上算不动；GPTQ 固定权重处理顺序，用 Cholesky 分解一次性批量更新剩余权重，把复杂度降到可在几 GPU 小时内完成千亿参数模型的量化 —— **不需要重训、不需要反向传播** |

理解要点：GPTQ 的"聪明"在于把量化误差**有方向地转移**（用二阶信息决定往哪放），加上工程上的批量更新让它变可行。题目不要求推导 Hessian 公式，能说清"误差往哪放、为什么这样放更好"即可。

### 4.2.3 AWQ：不是所有权重都同样重要

**Q1：AWQ 所说的 Salient Weight 是什么？为什么只保护少量重要权重也可能明显改善精度？**

- **Salient Weight**：对层输出影响最大的那些**权重通道**（典型只占 ~0.1%~1%）。它们的共同特征是**对应的输入激活幅值很大**（乘出来的贡献大）。
- **为什么少量就够**：因为 LLM 量化误差的主要来源是"少数关键通道被量化坏"，一旦保护住它们，剩下的权重即使量得粗一点，输出误差也很小 —— 这正好解释了两个经验现象：
  1. 保护 1% 的通道就能拿回大部分精度；
  2. 逐通道的激活幅值（而非权重本身的数值）才是"重要性"的正确度量。

**Q2：Activation Statistics 如何帮助判断哪些 Weight Channel 更重要？**

AWQ 用**校准集上的 per-channel 激活幅值**（如 `‖X_j‖` 的均值/最大值）作为重要性分数。直觉是：输出 `Y = Σ_j X_j W_{:,j}`，第 `j` 个权重通道是否重要，取决于它对应的激活 `X_j` 有多大——**即使权重数值很小，只要激活很大，它也很关键**（反之亦然）。所以是"用激活统计来做权重的重要性排序"。

**Q3：AWQ 为什么强调硬件友好，而不是简单地把少数权重留成高精度？**

因为"把少数权重留成 FP16"（混合精度/稀疏高精度）带来三个工程问题：

1. **Kernel 变复杂**：需要按掩码区分访问路径，无法用统一的 INT4 GEMM；
2. **反量化与访存变乱**：高精度通道要单独加载，破坏连续访问与向量化；
3. **实际收益被吃掉**：不规则内存访问 + 分支开销，可能让"省下来的比特"白省。

AWQ 的做法是**纯 per-channel 缩放**：把重要通道的权重乘上 `s > 1`（相对更容易被 INT4 表示，因为量化后再除以 `s` 时该通道的误差被缩小），同时把对应激活除以 `s`，保持数学等价；`s` 通过网格搜索最小化层输出误差。**结果所有权重仍然是统一的 INT4 布局**，Kernel 不需要任何特殊分支 → 硬件友好、可以直接跑标准 W4A16 GEMM。

### 三种方法的区别与适用场景（总结）

| | **SmoothQuant** | **GPTQ** | **AWQ** |
|---|---|---|---|
| 类型 | **W8A8**（激活 + 权重同量化） | **Weight-only**（W4A16 等） | **Weight-only**（W4A16） |
| 核心机制 | 数学等价的 per-channel 缩放，把激活 outlier 难度迁到权重 | 逐层最小化**输出重构误差**，用 Hessian 二阶信息决定误差分配，一次性批量更新 | 用**激活统计**挑出 salient weight，per-channel 缩放保护，保持统一 INT4 布局 |
| 需要校准数据 | 需要（算 `s` 与静态 scale） | 需要（算 Hessian） | 需要（算激活重要性 + 搜 `s`） |
| 省什么 | 权重 + 激活的存储/带宽，**并可用整数 GEMM 提速计算** | 权重存储/带宽（Decode 最痛的那一项） | 权重存储/带宽，工程实现最简单 |
| 实现复杂度 | 中（要改 Kernel 支持 W8A8） | 中（量化流程复杂，但推理 Kernel 成熟） | 低（标准 W4A16） |
| 典型场景 | 需要**提升吞吐/降低算力占用**的服务（8 bit 精度基本无损） | 单卡显存受限、需要**高质量 4 bit** 的大模型推理 | **端侧/边缘部署**、要求 Kernel 简单可靠、泛化性好 |

一句话选择建议：**要"更快"选 SmoothQuant（W8A8），要"更小"选 GPTQ/AWQ（W4A16）；其中 GPTQ 更偏精度、AWQ 更偏工程友好与泛化。**

## 4.3 一张卡仍然放不下：DP、TP 与 PP

先抓住一个问题：**每一种并行方式到底切开了什么？**

| 并行 | 切什么 | 每卡持有 | 通信 | 解决"装不下"吗 |
|---|---|---|---|---|
| **DP**（Data Parallel） | 数据 / 请求 | **完整模型** | 推理时几乎无通信（训练时梯度 All-Reduce） | ❌ 不解决 |
| **TP**（Tensor Parallel） | **层内的大矩阵** | 每层权重的一个分片 | 每层若干次 All-Reduce（层内通信） | ✅ 解决 |
| **PP**（Pipeline Parallel） | **层**（按深度切） | 模型的一部分层 | Stage 之间传 Activation | ✅ 解决 |

### Data Parallelism（DP）

每张 GPU 都保存完整模型，不同 GPU 处理不同请求或不同 batch。

- 优点：实现最简单，天然提升**整个服务的吞吐**；
- 局限：**单份模型仍要能装进一张卡**，所以 70B 放不进 24 GB 的问题，DP 单独解决不了；
- 代价：KV Cache 会在每张卡上各存一份（Task 3 的公式乘以副本数），显存压力不降反升。

### Tensor Parallelism（TP）

TP 把**同一层里的大矩阵**切到多张卡。以 MLP `H = GeLU(X·A)`、`Y = H·B`（`A: h×4h`、`B: 4h×h`）为例：

- **Column Parallel（列并行）**：**沿输出维切** `A` → `A₀ = A[:, 0:2h]`、`A₁ = A[:, 2h:4h]`。
  每张卡用自己的权重算出**不同的输出分片** `H₀`、`H₁`。因为 `GeLU` 是逐元素运算，**这一阶段完全不需要通信**。
- **Row Parallel（行并行）**：**沿输入维切** `B` → `B₀ = B[0:2h, :]`、`B₁ = B[2h:4h, :]`。
  每张卡算出的是**部分和** `Y₀ = H₀B₀`、`Y₁ = H₁B₁`，必须 `Y = Y₀ + Y₁` 才能得到真正的输出 → 需要一次 **All-Reduce**。

```text
X ──broadcast──┬──> [A₀] ─> H₀ ─> [B₀] ─> Y₀ ─┐
               │                               ├─ All-Reduce(Sum) ─> Y
               └──> [A₁] ─> H₁ ─> [B₁] ─> Y₁ ─┘
   无通信（Column Parallel）        有通信（Row Parallel）
```

**两卡 MLP 的切分图见 [`figures/mlp_tp_2gpu.svg`](figures/mlp_tp_2gpu.svg)**（标出了 Weight 如何切分、每张卡算出什么、Collective 发生在哪里）。

在真实 Transformer 里，`Q/K/V` 投影用 Column Parallel（**按 head 切分**，每卡拿一部分 head），输出投影用 Row Parallel，所以：

- 注意力计算本身每卡只处理自己的 head，**无需通信**；
- 只有输出投影之后要一次 All-Reduce；
- MLP 同理：`up/gate` 投影 Column Parallel → 激活（逐元素）→ `down` 投影 Row Parallel → All-Reduce。

**这就是"Column 与 Row 配对"的意义**：把通信收敛到**每层一到两次 All-Reduce**，避免无谓地把完整张量反复拼接。但层内通信仍然是 TP 绕不开的成本：**TP 适合放在带宽最高的互联上（NVLink/NVSwitch），通常限制在单机 8 卡内**。

### All-Reduce / All-Gather / Reduce-Scatter 各自收集或合并什么？

| Collective | 输入 | 输出 | 说明 |
|---|---|---|---|
| **All-Reduce** | 每卡一份同形状张量 | 每卡都得到**所有卡之和** | `Σ_i T_i`，结果在每张卡上完整复制。对应 Row Parallel 的"部分和求和" |
| **All-Gather** | 每卡一份**分片** | 每卡都得到**拼接后的完整张量** | 各卡分片按维度拼起来，结果每卡一份。用于需要完整激活/权重的场合（如收集完整权重做某些算子、SP 的逆操作） |
| **Reduce-Scatter** | 每卡一份同形状张量 | 每卡得到**求和结果的一部分分片** | 先按卡归约、再散播分片。是 Ring All-Reduce 的一半 |

工程要点：

- **All-Reduce = Reduce-Scatter + All-Gather**（Ring 实现的教科书结论），所以 All-Reduce 的通信量可以做到接近 `2 × (N-1)/N × 数据量`；
- **Reduce-Scatter / All-Gather 的配对**正是 Sequence Parallel 与 TP 配合时减少通信的关键：把 All-Reduce 拆成两步，可以在中间插入计算，减少峰值带宽压力；
- **NCCL 是这套 collectives 的标准实现**（`ncclAllReduce` / `ncclAllGather` / `ncclReduceScatter`），实际性能强依赖拓扑（NVLink / NVSwitch / PCIe / CXL）。

### Pipeline Parallelism（PP）

PP **按层切模型**：GPU 0 放前几层，GPU 1 放后几层，**Stage 之间传递 Activation**。

- 优点：单卡权重占用降到 `1/stage 数`；只传 stage 边界的激活，**通信量比 TP 小得多**，适合跨机（甚至跨机房）部署；
- 缺点：只有一个很小的 micro-batch 时，后面的 Stage 必须等前面的 Stage → **Pipeline Bubble**（流水线气泡，利用率下降）；
- 缓解手段：**Micro-batch** 提高流水线利用率（1F1B 调度等），但代价是**排队、吞吐与延迟的关系被改变**（micro-batch 变大 → 吞吐升、单请求延迟可能变差）。

### 三者对比与组合

| | 切分对象 | 通信内容 | 通信时机 | 通信量 | 适合的互联 |
|---|---|---|---|---|---|
| DP | 数据/请求 | 推理无；训练梯度 | 训练每步 | 大（整模型梯度） | 任意（通常跨机） |
| TP | 层内矩阵 | 激活（partial sum） | **每层** 1~2 次 | 中~大且**频繁** | NVLink/NVSwitch（机内） |
| PP | 层 | 激活 | 每 micro-batch 边界 | 小 | 跨机/跨节点 |

实际训练/推理系统通常是 **DP + TP + PP 三维组合**（如 Megatron-LM：机内 TP、跨机 PP、最外层 DP）。

### 回答：为什么三种并行可以叠加而不冲突？

因为它们在**不同的维度上切分**，互不干扰：

- **DP** 切的是"同一份完整模型跑多少份、各自处理哪批数据"；
- **TP** 切的是"同一层内的矩阵怎么分到多卡"；
- **PP** 切的是"层怎么按深度分到多个 stage"。

三者组合后，一张卡的显存需求 ≈ `(单层权重 / TP度) × (层数 / PP度)`，而总吞吐由 DP 副本数与 batch 决定 —— 于是"装不下"和"算得慢"两个问题被分开解决。

### 一句话总结这道题

- **量化**：把"每个参数 32 bit"压到 4~8 bit，理论上省 4~8 倍显存，但真正能省多少、能快多少，取决于**瓶颈是权重带宽、激活带宽、还是算力**，以及**硬件有没有对应的低比特路径**（Task 0 的 Roofline 在这里再次适用：量化本质是在降低 Memory Traffic，从而推高有效 AI）；

- **分布式**：DP 不动模型、TP 切层内矩阵（每层要通信、适合机内高带宽互联）、PP 切层（通信少但会起气泡、适合跨机）—— 三者在不同维度上切分，因此可以自由组合。
